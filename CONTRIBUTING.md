# Contributing

Thanks for helping! Bug reports, docs fixes and features are all welcome. For anything bigger than a small fix, please open an
issue first, so we can agree on the approach before you spend time on it.

## Development setup

You need Terraform >= 1.7 (or OpenTofu), Python 3.12+, `make` and `curl`.

```bash
make install     # Python venv, tflint, terraform-docs and the pre-commit hooks
make check       # pre-commit (fmt, docs, tflint, validate, black), terraform test, pytest
```

| Command | What it runs |
|---|---|
| `make test` | Lambda unit tests (pytest) |
| `make tf-test` | Terraform unit tests with mocked providers, no AWS account needed |
| `make pre-commit` | Formatting, linting, `terraform validate`, regenerated docs |
| `make e2e` | Deploys to a real AWS account and tests with curl and pip (see the README) |

## Making a change

1. Fork the repository and create a branch from `main`.
2. Make the change, with tests:
   - Lambda behaviour (`src/index.py`): a test in `src/test_index.py`.
   - Terraform behaviour (variables, conditional resources): a `run` block in `tests/main.tftest.hcl`.
3. Update the docs: input/output tables in the README are generated by `make docs` (pre-commit does it too), the rest by hand.
4. Add a line to the `## [Unreleased]` section of `CHANGELOG.md`. Mark breaking changes with **BREAKING:** and say how to
   upgrade.
5. Open a pull request. CI must pass: pre-commit, pytest, `terraform test` on Terraform and OpenTofu, and the Trivy scan.

If you change anything users can see at runtime (CloudFront behaviours, Lambda@Edge, IAM, the bucket policy), please also run
`make e2e` against a sandbox account and mention the result in the pull request.

## Style

- Terraform: `terraform fmt`, every variable and output has a `description`, inputs are validated where a wrong value would
  only fail at apply time.
- Python: formatted with Black, standard library plus `boto3` only (Lambda@Edge has no layers and a 1 MB package limit for
  viewer triggers).
- Keep defaults safe: a new option that weakens security must be opt-in.

## Releases

Maintainers release from `main` as described in the README ("Releasing"). Versions follow [SemVer](https://semver.org);
before `1.0.0`, breaking changes bump the minor version.
