# Contributing

Thanks for helping! Bug reports, docs fixes and features are all welcome. For anything bigger than a small fix, please open an
issue first, so we can agree on the approach before you spend time on it.

## Development setup

You need Terraform >= 1.7 (or OpenTofu), Python 3.12+, `make` and `curl`.

```bash
make install     # Python venv, tflint, terraform-docs and the pre-commit hooks
make check       # pre-commit (fmt, docs, tflint, validate, black), terraform test, pytest
```

| Command | What it runs |
|---|---|
| `make test` | Lambda unit tests (pytest) |
| `make tf-test` | Terraform unit tests with mocked providers, no AWS account needed |
| `make pre-commit` | Formatting, linting, `terraform validate`, regenerated docs |
| `make e2e` | Deploys to a real AWS account and runs the end-to-end suite (see below) |

## Making a change

1. Fork the repository and create a branch from `main`.
2. Make the change, with tests:
   - Lambda behaviour (`src/index.py`): a test in `src/test_index.py`.
   - Terraform behaviour (variables, conditional resources): a `run` block in `tests/main.tftest.hcl`.
3. Update the docs: input/output tables in the README are generated by `make docs` (pre-commit does it too), the rest by hand.
4. Add a line to the `## [Unreleased]` section of `CHANGELOG.md`. Mark breaking changes with **BREAKING:** and say how to
   upgrade.
5. Open a pull request. CI must pass: pre-commit, pytest, `terraform test` on Terraform and OpenTofu, and the Trivy scan.

If you change anything users can see at runtime (CloudFront behaviours, Lambda@Edge, IAM, the bucket policy), please also run
`make e2e` against a sandbox account and mention the result in the pull request.

## End-to-end test

`make e2e` deploys the module from your checkout to a sandbox AWS account and runs the pytest suite in `tests/e2e/suite`:
read auth and security headers, uploads (separate password, no overwrite, twine, `uv publish`, `poetry publish`), the PEP 503
pages and downloads, the cooldown, and installs with pip, uv and Poetry. The upstream is a fake index
(`tests/e2e/fake_upstream`, a Lambda behind a function URL) that serves made-up `cw-fake-*` projects with known upload times,
so every cooldown rule is checked exactly; other names are passed through to pypi.org as a smoke test. Then everything is torn
down (a few cents, 15-20 minutes):

```bash
AWS_PROFILE=sandbox AWS_REGION=eu-central-1 make e2e
```

Lambda@Edge functions can only be deleted a few hours after their CloudFront distribution, so the teardown may stop at the
function. Finish it later with `make e2e-destroy`.

`KEEP=1 make e2e` leaves the deployment up; `PYTEST_ARGS="-k cooldown" scripts/e2e.sh test` then re-runs part of the suite in
a minute. The suite is configured only through `E2E_*` environment variables (see `tests/e2e/suite/conftest.py`), so it can also
run against a deployment made another way, such as a wrapper module.

## Style

- Terraform: `terraform fmt`, every variable and output has a `description`, inputs are validated where a wrong value would
  only fail at apply time.
- Python: formatted with Black, standard library plus `boto3` only (Lambda@Edge has no layers and a 1 MB package limit for
  viewer triggers).
- Keep defaults safe: a new option that weakens security must be opt-in.

## Releases

Versions follow [SemVer](https://semver.org) with `v`-prefixed tags; before `1.0.0`, breaking changes bump the minor version.

Two commands. First list everything that goes out under
`## [Unreleased]` in `CHANGELOG.md` on `main`.

1. `make release VERSION=X.Y.Z` on `main`: makes the `release/vX.Y.Z` branch, turns `## [Unreleased]` into
   `## [X.Y.Z] - YYYY-MM-DD` with a fresh `## [Unreleased]` above it, updates the compare links at the bottom and
   `version = "~> X.Y"` in the README snippets, commits, pushes and prints the pull request link. Merge it once CI is green.
2. `make release-tag`: switches to `main`, pulls the merge and pushes the tag `vX.Y.Z`. The `Release` workflow publishes a
   GitHub Release with that version's `CHANGELOG.md` section as its notes. The Terraform Registry picks up the new tag
   automatically.
